3.1 DEFINICIÓN DEL SISTEMA

La definición debe explicar de manera científica qué es el sistema, qué problema funcional atiende, cuáles son sus entradas principales, qué procesa o decide y qué salidas o acciones produce. En esta etapa se describe la arquitectura a nivel funcional, sin convertir el texto en un catálogo detallado de componentes.

¿Qué es?Sistema, prototipo, dispositivo, plataforma, red, equipo, etc.
¿Para qué?Finalidad técnica coherente con el Objetivo General.
¿Qué recibe?Variables, señales, datos, eventos o entradas.
¿Qué hace?Mide, procesa, controla, comunica, supervisa, diagnostica, etc.
¿Qué entrega?Acciones, datos, alarmas, visualización, control, transmisión.
¿Dónde opera?Entorno real, institución, proceso, laboratorio o aplicación.
4

IDENTIFICACIÓN DE LOS SUBSISTEMAS PRINCIPALES

Un sistema electrónico complejo debe dividirse en bloques funcionales. La cantidad y nombre de los subsistemas depende del proyecto; no todos los proyectos necesitan los mismos bloques.

Regla metodológica: el nombre de cada subsistema debe expresar una función, no solamente el nombre comercial de un componente. Por ejemplo, es preferible “Subsistema de procesamiento y control” antes que “Arduino ESP32”.

TRES MODELOS DE FIGURAS PARA ORIENTAR EL DIAGRAMA DEL SISTEMA

Estas figuras son ejemplos didácticos. No deben copiarse literalmente: cada estudiante debe representar su propio sistema de acuerdo con el título, objetivo general, variables y flujo funcional.

CONTROL Y AUTOMATIZACIÓN

Ejemplo: control automático de nivel y caudal de un tanque didáctico

ELECTROMEDICINA

Ejemplo: monitor portátil de frecuencia cardiaca y saturación de oxígeno

TELECOMUNICACIONES

Ejemplo: enlace inalámbrico para telemetría de una estación meteorológica

Qué debe mostrar una buena figura general

✓ Nombre claro de cada subsistema.
✓ Flechas que indiquen el flujo de señales o información.
✓ Entradas y salidas principales.
✓ Bloque de alimentación cuando corresponda.
✓ Realimentación si existe control en lazo cerrado.
✓ Interfaz, comunicación o supervisión si forma parte del sistema.
✓ Numeración y título: Figura 3.x.
✓ Fuente: elaboración propia o fuente real correspondiente.

DESCRIPCIÓN CIENTÍFICA DE CADA SUBSISTEMA

Después de la figura general, cada subsistema debe describirse brevemente en párrafos científicos. En esta primera etapa no se desarrolla todavía el diseño detallado: se explica la función de cada bloque y su relación con los demás.

1. Nombre funcional“Subsistema de sensado”, “Subsistema de comunicación”...
2. FunciónQué responsabilidad cumple dentro del sistema.
3. EntradasQué señales, variables o datos recibe.
4. ProcesoQué tratamiento, conversión, decisión o transmisión realiza.
5. SalidasQué información, señal o acción entrega al siguiente bloque.
6. RelaciónCómo se integra con los demás subsistemas.

Ejemplo · Subsistema de sensado

El subsistema de sensado se encarga de adquirir las variables físicas necesarias para conocer el estado del proceso supervisado. Para ello, convierte las magnitudes de interés en señales eléctricas o datos digitales que pueden ser interpretados por la unidad de procesamiento. De esta manera, constituye la entrada informativa del sistema y proporciona los datos que posteriormente serán evaluados para ejecutar las acciones de control o monitoreo correspondientes.

Ejemplo · Subsistema de comunicación

El subsistema de comunicación permite transferir la información procesada entre el dispositivo electrónico y la interfaz de supervisión o infraestructura de red. Su función es organizar el intercambio de datos mediante el medio y protocolo seleccionados, manteniendo la continuidad del flujo de información. Asimismo, facilita que las variables medidas, estados o alarmas puedan ser consultados desde el punto de supervisión definido para el proyecto.

Viñetas: úsalas solo cuando sea estrictamente necesario enumerar características, requisitos, interfaces, parámetros o elementos técnicos. La explicación del funcionamiento del sistema y de los subsistemas debe realizarse principalmente mediante redacción científica en párrafos y conectores gramaticales.

HARDWARE, SOFTWARE Y FIRMWARE DENTRO DEL SISTEMA

🔧

Hardware

Parte física: sensores, etapas de acondicionamiento, microcontroladores, fuentes, actuadores, transceptores, interfaces, PCB, gabinete y demás elementos físicos.

💻

Software

Algoritmos, aplicaciones, interfaces de usuario, procesamiento, almacenamiento, visualización, programas de PC o nube y herramientas lógicas del sistema.

⚙️

Firmware

Software embebido cargado en el microcontrolador o procesador que hace que el hardware ejecute la lógica prevista y se integre con entradas, salidas y comunicaciones.

En muchos proyectos electrónicos, el funcionamiento real surge de la integración hardware + software + firmware. Sin embargo, no debe forzarse una categoría si el proyecto no la requiere; por ejemplo, un circuito puramente analógico puede no incorporar firmware.
